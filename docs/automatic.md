# 自動同期機能 詳細設計兼利用ガイド

本文書は、`skillset` におけるプロジェクトへのスキルセット自動同期機能（`roots` 管理、リポジトリ検出、同期処理、ファイルシステム監視、常駐サービス）の詳細設計および利用ガイドです。

`README.md` は手動機能と自動機能を網羅した全体の利用ガイドとして保守されています。本文書は、自動同期機能の具体的な挙動や詳細な仕様を規定する正式な参照先となります。

---

## 1. 概要と対象環境

### 目的と課題
従来の運用では、各リポジトリに対して手動でスキルセットを適用していました。本機能は、管理対象とする親ディレクトリをあらかじめ登録し、新規プロジェクトの作成やリポジトリの変更を検知して自動的にスキルセットを同期することを目的とします。ファイルシステムの定期的な全走査（ポーリング）を行わず、OSのイベント通知を利用することで、不要なリソース消費を抑えながら確実な反映を実現します。

### 対象環境と動作制約
- **言語および依存関係**: Python 3.11 以上の標準ライブラリおよび Git を使用します。追加の Python パッケージの導入は不要です。
- **OS サポート**:
  - 手動実行コマンド（`apply`, `remove`, `status`, `sync`, `roots` など）は、Linux および macOS で引き続き利用できます。
  - ネイティブ監視（`watch`）およびバックグラウンドサービス管理（`service`）は **Linux 専用** です。
  - 非対応のシステムで監視やサービスコマンドを実行した場合は、終了ステータス `2` と明確な診断メッセージを返して終了します。定期ポーリングによる代替動作は行いません。
- **対象ファイルシステム**: 本機能はローカルの Git 作業ツリーを対象とします。OS のファイル変更通知（inotify）を利用するため、ネットワークファイルシステム経由による別ホストからの変更など、OS イベントが発生しない操作の検知は保証されません。
- **走査の原則**: 定期的なファイル走査は行いません。ファイルシステム全体の走査は行わず、登録スコープ全体の走査（全体照合）も、起動時、設定変更時、および通知キューあふれ（IN_Q_OVERFLOW）、アンマウント、監視無効化からの復旧時のみに限定されます。通常のイベント発生時は、影響を受けたサブツリーのみを対象とします。

## 2. 設定とルートディレクトリ管理（roots）

### 設定ファイルの仕様 (`schema_version=1`)
設定ファイルは既存の形式（`schema_version=1`）を維持し、省略可能な `roots` オブジェクト（既定値は空の `{}`）を追加します。

```json
{
  "schema_version": 1,
  "sets": {
    "client-a": {
      "agents": [
        "codex",
        "claude"
      ],
      "skills": {
        "client-a-artifacts": "~/client-a/agent-skills/skills/client-a-artifacts"
      }
    }
  },
  "roots": {
    "/home/user/client-a": "client-a",
    "/home/user/client-a/experimental": null
  }
}
```

- **キー（ディレクトリパス）**:
  - 絶対パスまたは `~/` で始まるパスを指定します。内部でチルダ展開（`expanduser`）およびパス解決（`resolve(strict=False)`）によって正規化されます。
  - 正規化後に重複するキーの登録は拒否されます。
  - ファイルシステムルート（`/`）の登録は拒否されます（終了ステータス `2`）。過度に広範かつ破壊的な走査を防ぐためです。ホームディレクトリ自体（`~`）は明示的に指定された場合のみ許可されます。
  - 設定ファイル内のパスは、登録時点で実在しなくても構いません。後からディレクトリが作成された場合、監視機能がその出現を検知します。
- **値（割り当てセット）**:
  - 定義済みのセット名（文字列）、またはサブツリーの無効化を示す `null` を指定します。
  - セットの合成（複数セットの重ね合わせ）は行いません。
- **マッピングの解決規則**:
  - 単純な文字列の前方一致ではなく、パスの構成要素として解決された最長の祖先ディレクトリの設定を採用します。
  - 親ディレクトリでセットが指定されていても、子孫ディレクトリで `null` が設定されていればそのサブツリーは無効化されます。逆に、無効化されたツリー配下に明示的に有効なセットが登録されていれば、その子孫ディレクトリの設定が優先されます。
- **シンボリックリンクの扱い**:
  - 登録パスのシンボリックリンクは登録時に一度だけ解決されます。走査時にディレクトリのシンボリックリンクを追跡することはありません。
- **互換性と整合性保護**:
  - 未知のスキーマバージョンや未定義フィールドを含む設定ファイルは拒否されます（終了ステータス `2`）。
  - 内部モデルの初期化互換性（`Config(sets=...)`）は、既定値フィールドにより維持されます。
  - 設定ファイルの更新時は、ファイルに隣接するロックファイルに対して `flock` による非ブロッキングロック（競合時は終了ステータス `3`）を取得し、ロック下で最新状態を再読み込みした上でアトミックに書き込みます。既存の `sets` を含むすべてのデータを保持し、内容に変更がない場合はファイルの更新日時を変更しません。

### CLI 仕様 (`skillset roots`)
ルートディレクトリの登録・確認を行うサブコマンドです。実行には既存の設定ファイルが必要です（設定ファイルが存在しない場合は終了ステータス `2`）。

- **`skillset roots add DIR --set NAME [--config FILE]`**
  - 指定したディレクトリにセットを関連付けます。
  - 対象ディレクトリは、解決後に実在する通常のディレクトリである必要があります（存在しない場合や非ディレクトリの場合は終了ステータス `2`）。
  - 指定されたセットが設定ファイル内に存在することを検証し、正規化したパスで `roots[dir] = name` を保存します。
  - このコマンド自体はリポジトリの同期を行いません。
  - 成功時は標準出力に `registered\t<path>\t<set>` を出力し、終了ステータス `0` を返します。
- **`skillset roots disable DIR [--config FILE]`**
  - 指定したサブツリーを自動同期の対象から明示的に除外します（`roots[dir] = null` を設定）。
  - 対象ディレクトリは、解決後に実在する通常のディレクトリである必要があります（存在しない場合や非ディレクトリの場合は終了ステータス `2`）。
  - 既存のシンボリックリンクの削除は行いません。
  - 成功時は標準出力に `disabled\t<path>` を出力し、終了ステータス `0` を返します。
- **`skillset roots remove DIR [--config FILE]`**
  - 登録済みの正規化キーを削除します。
  - 冪等性を持ち、指定したパスが登録に存在しない場合やファイルシステム上に存在しない場合でも終了ステータス `0` を返します。
  - リンクの削除は行いません。キー削除後、上位の親ディレクトリにマッピングが存在する場合はそのマッピングが適用されます。
- **`skillset roots list [--config FILE]`**
  - 現在の登録一覧をソート順で表示する読み取り専用コマンドです。
  - 出力形式: `<path>\t<set名 または disabled>`
- **既存コマンドとの関係**:
  - 既存の `skillset status`、`skillset apply`、`skillset remove` の挙動に変更はありません。

## 3. プロジェクト検出と同期の内部設計

### データ構造と主要関数
設定モデルに `roots: dict[Path, str | None]` を追加し、検出・同期モジュール（`auto.py`）で以下の関数を提供します。状態を変更する関数は、文書化された終了ステータスを返すものを除き `None` を返します。

- **`select_set(config: Config, project: Path) -> str | None`**
  - プロジェクトパスに合致する最長一致のルートマッピングを調べ、適用すべきセット名を返します。合致するルールがない場合や無効化されている場合は `None` を返します。
- **`discover_projects(config: Config, start: Path | None = None) -> list[Path]`**
  - 有効な登録ルート配下に存在する実際の Git 作業ツリーのルートパスを、重複なくソートした一覧として返します。
  - `start` を指定した場合は、そのサブツリー（または `start` が祖先ディレクトリの場合は該当する登録子孫ルート）のみを探索します。
  - ディレクトリのシンボリックリンクは一切追跡しません。
  - 有効な Git プロジェクトの末端（リーフ）に到達した時点で、その配下の再帰探索を停止します（リポジトリ内に別のリポジトリがネストされている場合は、別途明示的なルート登録が必要です）。ただし、親ツリー内にリポジトリが存在していても、個別に明示登録された子孫ルートは走査されます。
  - 無効化されたサブツリーは探索を除外します（配下に明示的に有効化された子孫ルートがあればそれを優先します）。
  - **探索除外ディレクトリ名（`IGNORED_DIRS`）**:
    すべてのドットディレクトリを一律に除外するのではなく、以下の名前を明示的に探索対象から除外します。
    `.git`, `.skillset`, `.agents`, `.claude`, `node_modules`, `.venv`, `venv`, `__pycache__`, `.cache`, `.tox`, `.mypy_cache`, `.pytest_cache`, `.ruff_cache`, `.next`, `dist`, `build`, `target`, `vendor`
  - **Git プロジェクトの有効性判定**:
    1. プロジェクト候補直下の `.git` がシンボリックリンクではない通常のディレクトリまたはファイル（作業ツリーの `.git` ファイルなど）であること。
    2. `git rev-parse --show-toplevel` の解決結果が、候補パスの解決結果と完全に一致すること（ベアリポジトリは除外）。
    3. マーカーの欠損や不完全な状態のリポジトリはスキップし、OS レベルの例外は適切に報告します。
- **`sync_projects(config_path: Path, project_root: Path | None = None, *, dry_run: bool = False, quiet: bool = False) -> int`**
  - 呼び出しごとに最新の設定ファイルを読み込みます。設定ファイルが存在しない、または読み込みに失敗した場合は走査前に終了ステータス `2` を返します。
  - `project_root` が指定された場合は単一リポジトリを検証して適用し、マッピングが存在しない場合は `unmatched\t<path>` を出力して書き込みを行わずに終了ステータス `0` を返します。未指定時は検出されたすべてのプロジェクトを対象とします。
  - 各プロジェクトに対して既存の計画・ストレージ保護規則に従ってセットを適用し、結果を行単位で出力します。
  - **安全性保護規則**:
    - すでにリポジトリに記録されている `active_set` と今回選択されたセットが異なる場合は、競合として終了ステータス `3` を返し、過去に自動同期されたセットであっても勝手に切り替えることはしません。
    - 過去に手動で適用されたリポジトリであっても、適用中セットと今回選択されたセットが同一であれば同期を継続します。
    - 自身が管理していない既存のリンクやファイルを上書き・強奪することはありません。メタデータのシンボリックリンクや親ディレクトリの競合は処理をブロックします。
    - プロジェクト単体でエラーが発生しても、他の正常なプロジェクトの処理は継続します。
    - `dry_run` が指定された場合は、ファイル、ディレクトリ、ロック、除外設定の変更を行いません。
  - **終了ステータスの集約規則**:
    1. 入出力エラーまたはデータ破損が発生した場合: `1`
    2. 上記に該当せず、競合、ロック競合（ビジー）、保留中がある場合: `3`
    3. 上記に該当せず、無効な選択元の指定がある場合: `2`
    4. すべて正常に完了した場合: `0`

### Git ローカル除外設定（`info/exclude`）の自動登録
正常に同期されたプロジェクトでは、管理用ディレクトリおよびシンボリックリンクが Git の追跡に混入しないよう、Git ローカルの除外ファイルに自動登録します。

- **対象ファイル**: `git rev-parse --path-format=absolute --git-path info/exclude` で取得されるローカル除外設定ファイルです。作業ツリー内の `.gitignore` やコミット対象ファイルは一切変更しません。
- **登録内容**: リポジトリルート基準の `.skillset/` および生成されたシンボリックリンクの相対パス。
- **保護と排他制御**:
  - 事前に `git ls-files` を検証し、リンクの配置予定先やその配下が Git で追跡されていないことを確認します。追跡対象のファイルをスキルセットの管理対象に置き換えることはできません。
  - `info/exclude` がシンボリックリンクまたは通常ファイル以外である場合は処理を拒否します。この検証はリンク編集前に事前実行されます。
  - 既存のバイト列を保持し、未登録の行のみを末尾に追記します（重複登録の防止）。
  - 作業ツリー間で除外ファイルを共有している環境を考慮し、隣接する専用の永続ロックファイルを用いた `flock` により読み書きを直列化します。
  - 管理対象となる配置先パスに改行コードが含まれる場合は、インジェクション防止のため処理を拒否します（スペースを含むパスは許容）。
  - ルート登録の削除時に、除外設定からの削除は行いません。また、同期が競合して失敗した場合は除外設定の追記も行いません。

### 手動同期コマンド (`skillset sync`)
エージェント起動前などに、利用者が明示的に同期を実行できるコマンドです。

```bash
skillset sync [--project-root DIR] [--dry-run] [--config FILE]
```

- `--project-root`: 指定した単一リポジトリのみを対象に同期します。
- `--dry-run`: 実際のファイル作成、ディレクトリ変更、ロック取得、Git 除外設定の更新を行わず、適用の検証結果のみを表示します。
- **補足**: エージェント（Codex や Claude など）の起動コマンドを書き換えるようなラッパーの自動注入は行いません。

## 4. ネイティブイベント監視（skillset watch）

Linux の `inotify` を利用し、ファイルシステムの変更イベントに応じて自動同期を行うフォアグラウンドプロセスです。

```bash
skillset watch [--config FILE]
```

### アーキテクチャとリソース制御
- **ネイティブバインディング**: `ctypes` 経由で Linux の `libc` システムコールを直接呼び出します。ファイルディスクリプタには非ブロッキング（`O_NONBLOCK`）および実行時クローズ（`O_CLOEXEC`）を指定します。
- **待機制御**: 処理すべき保留タスクがないときは、`selectors` を用いてブロッキング待機します。定期的なファイル走査や更新日時（mtime）のポーリングは一切行いません。
- **タイマーの用途**:
  - 短時間の待ち合わせ（デバウンス、約0.2秒）
  - Git 作業ツリー作成途中の有界な再試行（0.2秒、0.5秒、1秒、2秒、5秒の間隔）
  - 終了シグナル（SIGINT / SIGTERM）の安全な受信（終了ステータス `0` で正常終了）
- **多重起動防止**:
  - 設定ファイルごとに単一の監視デーモンのみ稼働を許可します。
  - ランタイムディレクトリ（`${XDG_STATE_HOME:-~/.local/state}/skillset`）配下に `watch-<config_hash>.lock` を作成し、非ブロッキングの `flock` を保持します（競合時は終了ステータス `3`）。稼働中のロックファイルをアンリンクすることはありません。

### 起動シーケンスと監視境界の確立
1. 設定ファイルを読み込みます。
2. ファイルシステムの走査を開始する前に、まず設定ファイルの親ディレクトリ（または直近の既存祖先ディレクトリ）の監視を登録します。
3. ディレクトリ探索境界となるディレクトリ監視を登録した上で、既存リポジトリの走査を行い、それぞれ1回初期同期を実行します。
4. **監視対象の範囲**:
   - 各リポジトリのルートおよびその直下の `.git` ディレクトリ（メタデータ変更の検知用）を非再帰的に監視します。ソースツリー配下のファイル全体を再帰監視することはありません。
   - ネストされた登録スコープに至るまでの祖先ディレクトリも監視対象に含めます。
5. **ディレクトリ登録の順序**:
   - 新規サブツリー作成時の競合を防ぐため、**子要素を列挙する前にディレクトリを監視対象として登録** します。新規作成または移動してきたディレクトリを監視下に置いた後、その内部の既存コンテンツを走査します。
   - `IGNORED_DIRS` に含まれるディレクトリは監視・走査から除外します（`.git` 直下の非再帰監視を除く）。シンボリックリンクの追跡や、`.agents` 配下のキャッシュリポジトリ走査は行いません。

### イベント処理と耐障害性
- **Git 操作・作業ツリー作成の検知**:
  - 新たな `.git` マーカーやメタデータの変更を検知すると、同期候補としてキューに入れ、約0.2秒のデバウンス後に検証を行います。
  - `git worktree` や `git clone` の作成直後でメタデータが不完全な場合は、有界な間隔（0.2秒、0.5秒、1秒、2秒、5秒）で再確認します。途中で新たなイベントを受信した場合は試行回数がリセットされます。上限に達した場合は保留としてログを記録し、その後のファイルイベントを待機します（定期ループによる CPU 消費を防ぎます）。
  - `git clone` の完了に時間がかかる場合でも、その後の `HEAD` や設定マーカーの更新イベントによって検証がトリガーされます。
  - 既存の健全なリポジトリ内における通常のソースファイル編集イベントは無視されます。
- **局所的な同期の実行**:
  - 通常の変更イベントでは、影響を受けたプロジェクトのみを同期します。全登録ルートの再走査は行いません。
  - ディレクトリの名前変更や削除が発生した場合は、必要に応じて監視マッピングを更新・再構築します。
  - キュー内の処理を実行する直前に、対象が現在も有効なスコープ内に存在するかを再確認します。ディレクトリ移動によってスコープ外へ出たパスに対して書き込みを行うことはありません。
- **自己誘発ループの抑止**:
  - 自身が生成・更新する `.skillset`、`.agents`、`.claude` の変更イベントは無視します。
  - `info/exclude` の更新が自己ループを引き起こさないよう制御します。
- **設定ファイルの動的再読み込み**:
  - 設定ファイルの書き込み完了（`close-write`）、アトミックな置換、削除を監視します。
  - 設定が更新された場合、監視の再構築と全体照合を1回実行します。
  - 設定ファイルに文法エラーや不正な内容が含まれる場合は、変更処理を一時停止してエラーをログに出力し、修正されるまで設定ファイルを監視し続けます（過去の正常設定を無理に適用し続けることはしません）。設定エラーによって監視プロセスが終了することはなく、マッピングが削除された場合でも既存リンクの削除は行いません。
  - 登録ディレクトリが存在しない場合は、直近の存在する祖先ディレクトリを監視して復元を待ちます（プロセスが勝手にディレクトリを作成することはありません）。
- **キューあふれと異常系の復元**:
  - inotify のキューあふれ（`IN_Q_OVERFLOW`）、ファイルシステムのアンマウント、監視の無効化を検知した場合は、警告を記録した上で監視を再構築し、全体照合を1回実行します。
  - システムの監視上限（watch-limit）超過など永続的な障害が発生した場合は、無限ループに陥らずに対処可能なエラーとして終了ステータス `1` を返します。
  - 登録ルートディレクトリ自体が削除されても監視プロセスは終了せず、祖先ディレクトリを監視して再作成を待機します。
- **ログと出力**:
  - 起動完了時に `watch: ready` を標準出力にフラッシュ出力します。
  - 待機中は沈黙を保ち、実際に同期が行われたリポジトリの変更やエラーのみをログ出力します。

## 5. バックグラウンドサービス管理（skillset service）

Linux の `systemd --user` を利用して、監視デーモンを常駐管理するコマンド群です。

```bash
skillset service {install,start,stop,status,uninstall} [--config FILE]
```

### 設計原則
- **対象環境**: Linux かつ `systemd --user` に接続可能な環境に限定されます。非 Linux 環境では終了ステータス `2`、systemd ユーザーサービスが利用できない、または到達不能な環境では明確に終了ステータス `1` を返します。
- **権限分離**: 管理者権限（`sudo`）やシステム全体のユニットは一切操作しません。ユーザー空間でのみ完結します。

### サブコマンド仕様
- **`install`**
  - ユニットファイル `skillset-watch.service` を `${XDG_CONFIG_HOME:-~/.config}/systemd/user/` 配下に生成します。
  - 実行コマンド（`ExecStart`）には、現在の Python 実行バイナリ、ランチャー、設定ファイルの絶対パスを正確にクォートおよびパーセントエスケープして記述します。
  - 自身が管理するユニット以外の既存ファイルが存在する場合は、誤上書きを防ぐため終了ステータス `3` で拒否します。
  - ユニットファイルを配置後、`systemctl --user daemon-reload` および `systemctl --user enable --now skillset-watch.service` を実行して即座に有効化・起動します。
- **`start`**
  - `systemctl --user start skillset-watch.service` を呼び出し、サービスを開始します。
- **`stop`**
  - `systemctl --user stop skillset-watch.service` を呼び出し、サービスを停止します。
- **`status`**
  - `systemctl --user status skillset-watch.service` を実行し、systemctl の出力をそのまま表示して終了ステータスを引き継ぎます（サービス停止中は終了ステータス `3`）。
- **`uninstall`**
  - `systemctl --user disable --now skillset-watch.service` を実行して停止・無効化し、配置したユニットファイルを削除した上で `systemctl --user daemon-reload` を実行します。

## 6. 導入手順と運用ガイド



1. **管理対象ディレクトリの登録**:
   ```bash
   skillset roots add ~/client-a --set client-a
   ```
2. **同期の事前確認（ドライラン）**:
   ```bash
   skillset sync --dry-run
   ```
   適用予定の内容を確認し、競合が発生しないことを検証します。
3. **手動同期の実行**:
   ```bash
   skillset sync
   ```
   既存リポジトリへの初期同期と Git ローカル除外設定（`info/exclude`）の更新を完了させます。
4. **常駐サービスの登録と起動**:
   ```bash
   skillset service install
   ```
   systemd ユーザーサービスとして監視デーモンがバックグラウンドで起動します。

### 運用上の注意点
- **エージェント起動前の明示的同期**:
  IDE やコーディングエージェント（Codex、Claude など）を起動する直前に最新状態を確実に揃えたい場合は、利用者が手動で `skillset sync --project-root <リポジトリパス>` を実行できます。本ツールはエージェント起動ラッパーの自動書き換えを行いません。また、GUI エディタなどのファイル読み込みより先に対象ファイルが存在するような同期タイミングの即時保証はないため、確実性を要する場合は作業開始前のコマンド実行を推奨します。
- **ネットワークファイルシステムに関する制限**:
  本機能のイベント検知はローカルマシンの inotify に依存しています。他ホストから共有ストレージ経由でファイルを変更した場合など、OS の通知が発行されない操作は検知できません。ローカル環境での Git 作業ツリー運用を前提としてください。
